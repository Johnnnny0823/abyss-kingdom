# Codex 派工：AI 試玩（一系列自動遊玩與試玩報告）

**排在 `HANDOFF-PLAYTEST-TELEMETRY.md` 驗收之後再做**（要用到它的遊玩紀錄與回饋功能）。
目的：在找朋友封測前，先用 AI 把「新玩家前 60 分鐘」完整玩幾遍，找出卡關、錯誤、看不懂的地方。對應 `docs/PLAYTEST_CHECKLIST.md`。
**限制要寫進報告**：AI 試玩能抓到壞掉、卡住、不清楚的地方，但**不能代替真人判斷好不好玩**；使用者的 A5 與朋友封測照常進行。

## 共通規則

- 只用本機 Dev（`Auth__Mode=Dev`、`Storage__Mode=InMemory`、5090 埠）與專用 dev 帳號（`dev-aiplay-<角色>`）。**不要用使用者的訪客帳號，不要連正式伺服器或正式資料庫。**
- 試玩只能透過**玩家看得到的協定與介面**行動，不可用 GM 端點給資源或改等級（否則測不到真實節奏）。GM 端點只用來讀紀錄。
- 遇到 bug **先記錄、不要邊玩邊修**；修正另開派工，交給使用者決定。
- 不 commit、不 push、不部署；完成後交 Claude 驗收。

## 第一部分：協定層試玩機器人（快、可重複）

在 `tools/` 下新增 `AiPlaytest`（或擴充 `tools/NewbieSim`，二擇一並說明理由），用真的 WebSocket 連本機 Dev 伺服器，扮演下面四種玩家。伺服器時間要能加速（例如 Dev 專用的時間倍率環境變數，**正式模式必須無效**，並加測試證明），才不用真的等 60 分鐘。

| 角色 | 玩法 | 要回答的問題 |
|---|---|---|
| 照任務走 | 每一步只做任務欄「前往」會帶去的事 | 第一章能不能全部完成？哪一步最久？有沒有任務沒有路可走 |
| 勤勞玩家 | 隊列永遠不空、資源夠就升級、會出征採集與打營地 | 60 分鐘能到哪裡？哪裡開始只能乾等 |
| 隨便點 | 隨機合法操作，偶爾送不合法的（資源不夠、前置不足、重複點擊） | 伺服器會不會出錯、狀態會不會壞、錯誤訊息有沒有對應的中文 |
| 離線回來 | 玩 15 分鐘、離線 8 小時、再玩 15 分鐘 | 離線收益、隊列完成、護盾、傷兵是否正確，回來後知不知道要做什麼 |

每個角色輸出時間軸（遊戲內分鐘 → 做了什麼 → 資源與等級），並和 A4 的 `GET /admin/playtest/summary`、`/events` 對照，確認紀錄正確。

## 第二部分：真實客戶端試玩（看畫面）

用打包版客戶端（可加新的 `-aiplaytest` 診斷參數，照 `Diagnostics/` 既有檢查的寫法，只在 loopback Dev 生效）照「照任務走」的路線實際操作介面，每個任務與每個主要畫面截圖：城內、大地圖、主將、遠征、兵營、背包、醫館、聯盟、出征面板、各資訊卡與錯誤提示。

逐張檢查並記錄：
- 文字重疊、被切掉、超出框、中英混雜或還沒翻譯的字。
- **每個圖示能不能點開看名稱與說明**（專案規則）。
- 按鈕點了沒反應、彈窗關不掉、鏡頭跑到奇怪的地方、模型穿插或缺圖。
- 新玩家看了會不會懂下一步要做什麼（只記錄「看不懂」的具體地方，不評論好不好玩）。
- 送一則回饋、觸發一次錯誤，確認 B1／B2 在真實介面可用。

## 交付：試玩報告

寫成 `docs/AI_PLAYTEST_REPORT.md`：

1. **一頁摘要**：四個角色各自玩到哪裡、第一章完成時間、60 分鐘時的主堡與建築等級。
2. **問題清單**，依嚴重程度排序：
   - 🔴 卡關或壞檔（玩不下去、資料錯誤、伺服器錯誤）
   - 🟠 明顯 bug（功能錯、數字錯、按鈕無效）
   - 🟡 看不懂或不順（新手不知道下一步、提示不清楚）
   - ⚪ 小瑕疵（排版、錯字）
   每一項附：重現步驟、截圖或 log 路徑、可能原因（猜的就標「推測」）。
3. **節奏觀察**：哪段最忙、哪段開始乾等、和 GDD 4.1 記錄的新手節奏比較。
4. **建議的下一步**：最多 5 項，讓使用者挑；不要自行實作。
