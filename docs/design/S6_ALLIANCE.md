## 1. 已確認範圍與交付方式

使用者在本次 grill-me 問答確認：

2. 集結先打 PvE 營地／強怪，為之後全服 BOSS 建基礎；援軍參與盟友城防。集結攻城、可摧毀盟旗延後。
3. 幫助與軍事容量先由主堡等級控制，使用聯盟介面操作；不新增外交／指揮建築與其模型。**2026-10-12 使用者修訂（尚未實作）：之後新增大使館，改由大使館等級決定幫助次數／效果與援軍接收容量，並作為主堡升級前置，見 GDD 5.9。** 本版 S6 仍照主堡等級交付。
4. 集結每人一位主將，最多五人。**2026-10-12 使用者修訂：集結與援軍都可由一位主將混編全部三種兵，個人可派總兵數由建築等級決定，等級越高可派越多。** 沿用先前確認的主堡作為容量建築；取代先前單兵種與個人統率上限設計。每城最多接收一支援軍的席位限制維持不變。
5. 每盟最多三面旗、領地須連接、異盟領地不重疊、撤旗／搬旗有冷卻；不阻擋其他人定居或行軍。
6. 其他細節由本提案給完整建議值，交使用者一次審閱，不逐項打斷討論。

首版不含：聯盟科技／商店／付費禮物、外交條約、王城戰、盟旗攻防、跨服、遷城系統、世界 BOSS 本體、專用新建築。不能把「預留未來用途」寫成已完成的玩法。

## 2. 玩家體驗與基本數值（建議）

目標：新手主堡二級後就能加入、聊天與互助；中期透過駐軍與集結形成合作，盟旗讓聯盟在地圖上有可見據點。第一版不把開荒資源轉成永久圈地優勢。

| 項目 | 首版建議 |
| --- | --- |
| 加入聯盟 | 主堡 Lv.2；免費；一位玩家同時一盟 |
| 建立聯盟 | 主堡 Lv.3；根材 5,000＋層岩 5,000；無付費貨幣；成功成立才完成扣款 |
| 人數上限 | **40**（2026-10-12 使用者改定）；之後聯盟科技每級 +2，見 GDD 5.4；不增加付費擴容 |
| 名稱／簡稱 | 名稱 2～16 字元；簡稱 2～4 個英文字母／數字，統一大寫；同服名稱與簡稱唯一 |
| 階級 | 盟主、幹部、成員；一位盟主、最多四位幹部 |
| 加入模式 | 創立時預設自由加入；盟主可改需審核；不做邀請碼與私密盟 |
| 入盟申請 | 最多同時向三盟申請，24 小時過期；一旦入盟其他申請自動失效 |
| 退出／被踢 | 之後 24 小時不能再加入或建立；首次加入沒有等待 |
| 幫助 | 建築升級與醫館治療；訓練暫不包含，科技等科技系統推出才接入 |
| 軍事解鎖 | 主堡 Lv.3 可派／收援軍與發起／加入集結 |
| 集結人数 | 發起者也佔一席，最多五個不同玩家；至少兩人到齊才出發 |
| 集結倒數 | 發起者選 60／180／300 秒，預設 180 秒 |
| 援軍容量 | 個人派援上限建議 100×自己的主堡等級；接收上限建議 100×收援城主堡等級。三兵種加總同時滿足兩者，不再另受主將統率限制；使用者已核准建議值 |
| 個人集結派兵容量 | 建議 100×自己的主堡等級，三兵種人數加總計算；集結不再另取主將統率作人數上限，主將仍影響戰鬥屬性。使用者已核准建議值 |
| 集結總容量 | 建議 500×發起者主堡等級，另有最多五人限制；總容量與各人容量須同時滿足，使用者已核准建議值 |

數值全放 shared 的設定中，以整數與 Unix 毫秒計算。倒數不以客戶端時間判定，容量降低不追溯刪兵；既有部隊依建立時上限完成，新派遣採新上限。

名稱比較：Unicode 正規化、去頭尾空白、英文字母不分大小寫；拒絕控制字元、換行與富文字標記。長度以 Unicode 字元計數而非 UTF-16 長度；禁止名稱清單由伺服器檢查。新增中文顯示詞只是草案，核准後集中在 DisplayNames 與 GDD，程式 enum 用英文。

## 3. 成員、權限與盟籍變更

| 操作 | 盟主 | 幹部 | 成員 |
| --- | --- | --- | --- |
| 聊天、幫助、派援、集結 | 可 | 可 | 可 |
| 審核入盟 | 可 | 可 | 不可 |
| 踢一般成員 | 可 | 可 | 不可 |
| 踢幹部、任免幹部 | 可 | 不可 | 不可 |
| 修改公告、審核模式 | 可 | 可改公告 | 不可 |
| 插旗、撤旗 | 可 | 可 | 不可 |
| 轉讓盟主、解散 | 可 | 不可 | 不可 |

- 不可踢自己、盟主或同級幹部；盟主不能直接退出，必須先轉讓給現有成員，或在只剩自己時解散。
- 盟主可指定任一現有成員接任，不需雙方同時在線；轉讓須二次確認，舊盟主轉為一般成員。首版不自動罷免離線盟主，GM 介入須記錄原因。
- 解散只允許唯一成員、沒有未完成操作／軍隊／旗幟；先召回與撤旗，避免帳面已解散但兵仍駐外。
- 離盟／踢人立即取消新操作權限。已登記的跨玩家結算先完成；在途援軍折返、駐軍返還、集結按下節規則處理。UI 如實顯示「離盟處理中／軍隊返還中」，不假裝瞬間回到兵營。
- 防守／集結已凍結的參與資格，不因途中被踢而刪除其戰損或獎勵；離盟不構成取消戰鬥的漏洞。
- 入盟後不可攻擊同盟城市。既有攻城行軍途中雙方成為盟友，抵達時再次檢查，未開始結算就無損折返；已開始結算的戰鬥照原紀錄完成。
- 前述每次入盟有新的 membership epoch；退盟再加入不繼承舊申請／幫助資格。相同玩家不能藉 epoch 重置反覆幫同一隊列。

## 4. 聯盟聊天與可點擊說明

- 聯盟頁預設顯示公告、線上／總人數與最近聊天；聊天純文字，每則最多 200 字，歷史保留最近 100 則且最多七天。
- 每人最短兩秒一則，另限制每分鐘 20 則；相同請求重送不能多發。先持久化，再回 ACK／廣播；重連帶最後序號補發，過舊則回最近歷史。
- 只推給當下盟員，離盟立刻取消訂閱；新成員可看目前保留的聯盟聊天。角色／盟籍在每次請求重新驗證，不信任客戶端 allianceId。
- 可檢舉並帶 messageId；盟主／幹部可隱藏訊息、禁言一般成員 1 小時或 24 小時；對幹部的處置由盟主執行。管理動作留稽核紀錄。首版不自動 AI 審查、不接付費服務。
- 大地圖名牌格式 `[簡稱] 領主名`；沒有聯盟就只顯示領主名。全圖可切換領地覆蓋，使用顏色加紋理／標籤，避免只靠紅綠辨識。
- 每個資源、幫助、援軍、旗幟、容量、獎勵圖示都能點擊，顯示名稱、用途、取得方式／解鎖條件。圖示旁顯示文字與可用／上限；禁用按鈕說明理由。文字集中 DisplayNames。
- 先使用現有圖示／程式旗標顯示；若之後需要正式盟旗模型，再單獨提需求，不在 S6 偷加建模工作。

## 5. 聯盟幫助

### 操作與公式

升級或治療開始後出現「請求幫助」；聯盟頁有「幫助全部」，伺服器逐項驗證，回傳成功／失效件數。

- 隊列持久化穩定 queueId，不能用可變完成時間或陣列索引當 ID。記錄原始時長 D、已縮短量、已幫助者 ID、请求時盟籍。
- 次數上限 `min(10, 2 + 主堡等級)`，建立請求時鎖定；本人不可幫自己，同一玩家每個 queueId 一次。
- 單次縮短 `min(60,000, max(1,000, D / 100))` 毫秒，整數除法向下取整。
- 所有幫助合計不超過原始時長 20%，實際縮短再取「剩餘總額度、當下剩餘時間、單次上限」三者最小值；可以恰好完成，不產生負時間。已完成／取消不消耗幫助次數。
- 原始時長是扣除既有建造速度規則後、尚未用道具或聯盟幫助前的時間；用道具不重置幫助上限。升級完成採既有 CityLogic.Advance 流程，不能另寫一套發獎。
- 資格以伺服器接納幫助時為準：同盟、未被踢、請求有效；接納後遇存檔重試仍完成一次。離盟撤掉未接納的請求，重新入盟可重新掛出，但原 queueId 的額度與已幫助名單不清空。
- 援助人不獲可交易貨幣，第一版避免刷幫助經濟。可顯示累計幫助次數，計數也按 operationId 去重。

例：原始 10 分鐘隊列，一次縮短 6 秒，最多十人共 60 秒；短隊列最多仍只能縮原始時長的 20%。

## 6. 援軍駐守

### 派遣與容量

- 一支援軍＝一位主將＋自由混編的一至三種兵，原玩家扣除實兵、占用一個既有行軍位與該主將；不把兵加入收援方兵營。
- 每城最多一支援軍，**在途即預留席位**。三種兵加總不得超過派出者主堡派兵容量與收援方主堡接收容量，超額直接拒絕並顯示上限，不暗中裁切；不再另以主將統率壓低援軍人數。
- 例如派出者主堡 Lv.4、收援方 Lv.3，按建議公式最多派 300 人，可分配為磐盾衛 100＋鳴弦手 120＋裂蹄騎 80；收援方升到 Lv.4 後，新派遣可到 400 人。升級不自動補兵，仍須實際擁有相應兵力。
- 派遣需雙方同盟，接收設定預設開啟；收援方可关闭新派遣／遣返，派出方可召回。城防尚未凍結時召回生效，已進入戰鬥結算則結算完再回。
- 路徑沿用現有關隘 Dijkstra。狀態：`Reserved → Traveling → Garrisoned → Returning → Returned`；與戰鬥狀態交接時持久化 settlementId。
- 援軍抵達前不能參戰；滿血／殘兵都占同一席，歸零時立即結束駐守但仍需完成傷兵結算、釋放主將。

### 城防、戰損與護盾

- 防守最多：本城三兵種小隊＋援軍三兵種小隊＋一城防＝七小隊。援軍仍只有一位玩家的一位主將，人數最多的兵種由該主將带領、其他兵種由隊長帶領；沿用既有混兵展開的同數量決勝順序，不複製主將加成、不合併不同玩家兵力。援軍各小隊插在城防之前，城防仍在最後。
- 戰鬥核心須由伺服器選擇援軍城防模式，支援最多七個守方 SquadInput；未參與援軍的原有戰鬥仍維持原限制。各援軍兵種都記錄同一 ownerId／marchId，戰損逐兵種歸還原擁有者。
- 援軍不保護資源免掠奪；贏敗、城防和掠奪按既有 PvP。援軍不分享守方資源，也不能被收援方拿去出征。
- 援軍傷兵回派出者醫館，死亡比例和溢出規則沿用 70% 傷兵；容量不足在實際套用傷兵時判斷。存活者繼續駐守，除非已要求召回。駐外主將仍不能再出征。
- 收援城有護盾，攻城被擋，援軍不觸發戰鬥。派援與參與防守不解除派出者護盾；護盾不讓派出的兵免受戰損。PvE 集結也不解除護盾。
- 收援／派出任一方離盟，尚未凍結戰鬥的援軍返還；凍結後先完成該場戰損再回。斷線照常駐守，不假設玩家在線。
- 新手盾不能被援軍繞過；援軍不能援助敵盟或自己。未來加入遷城時，須先確認無駐軍／援軍在途，或另訂遷移規則；本版不新增遷城。

## 7. 盟旗與領地

### 放置、成本與限制

| 項目 | 建議值／規則 |
| --- | --- |
| 旗數 | 每盟最多 3 面，包含建造中 |
| 成本 | 第 1／2／3 面各需根材與層岩 10,000／20,000／30,000，由操作的盟主／幹部個人支付 |
| 聯盟公庫 | 首版不做，不引入捐獻或新聯盟貨幣；費用及付款人需二次確認 |
| 建造 | 5 分鐘，施工時預留領地衝突但不提供加成；不占個人建築隊列，不可加速／幫助 |
| 覆蓋 | 旗點同一分區內，可步行格的四方向最短距離 ≤12 格；不能穿越山體／深淵／關隘向另一環延伸 |
| 第一旗 | 同盟任一成員城中心 10 格內，且同一分區、可通行連接 |
| 後續旗 | 領地與已啟用領地有交集或四方向相鄰；不可越環飛地 |
| 衝突 | 不得與其他盟的有效或施工中領地重疊；不因佔領地就禁止其他領主定居 |
| 旗點排除 | 主城所有候選佔地、資源／營地／入口佔地、關隘通道；不能蓋在固定玩法物件上 |
| 撤旗 | 立即失效、不退款；只能撤不會讓剩餘旗群斷開的末端旗 |
| 重建冷卻 | 撤旗或取消施工後該槽位 24 小時才能再建；搬旗＝撤旗＋重建，不免費瞬移 |
| 建造取消 | 盟主／幹部可取消，不退款；取消不解除已使用槽位的冷卻 |

費用依所選槽位固定，不以目前旗數鑽便宜旗成本。施工中不作其他旗的連接根；撤掉支撐旗前必須先取消其依賴的施工。刪最後一旗後，重新建第一旗同樣受該槽冷卻。

旗幟不占行軍障礙；覆蓋其他玩家已住的格可以，但不給非盟友加成、不驅逐、不禁採。第一版不能摧毀旗，故範圍與數量刻意有限；不添加永久搶點積分或稀有資源。

### 加成與時間邊界

- 採集速度 +10%（乘 11000 / 10000），不增加田存量或載重；一田一隊規則不變。
- **按開始採集時快照**：當時是盟員且田中心在本盟有效領地，該次採集全程使用此倍率，直到返程；退盟／撤旗不重算過去收益，也不追扣。下一次採集重新判定。持久化倍率與採集起止，離線／重啟相同。
- 防守 +5% 防禦（乘 10500 / 10000），以戰鬥凍結時城中心是否在本盟有效領地判定；適用本城守軍、城防與該場合法援軍。
- 同盟旗覆蓋不疊加；不同來源未來加成如何合成由之後規格訂，S6 不先造通用增益系統。
- `now >= completesAtMs` 才生效。旗施工占位、完工、撤旗與並行放旗由同一權威領地狀態序列化；顯示可延後一幀，規則不能使用客戶端色塊判定。
- 遷城折扣仍屬未來功能，UI 不顯示尚不可用的折扣承諾。

## 8. PvE 集結

### 組隊、移動與取消

1. 選尚存的 Lv.2／Lv.3 營地發起（Lv.1 留給單人）；建立時選一位主將、三兵種各自人數、倒數，预留並扣除發起者實兵，鎖定其主將與一個行軍位。可只派一種或混派兩／三種，總數須為正且不超過自己的主堡容量及集結剩餘總容量。
2. 同盟成員加入，預留席位／容量後，沿現有路徑前往發起者主城集結；同一人不得佔兩席。顯示預計抵達時間，只允許 ETA 不晚於出發時間的派遣。
3. 倒數到期，先推進所有到時應抵達的隊伍；`arrivalMs <= departMs` 算到齊。凍結實際到齊名單，至少含發起者與一名盟友，否則取消並逐隊返還。
4. 最多五位主將、五支玩家行軍；每支依實際兵種展開一至三個戰鬥小隊，攻方最多十五個 SquadInput。建議沿用普通混兵行軍的人數最多兵種由該玩家主將帶領、其他兵種由隊長帶領的規則；不憑空多複製兩位主將屬性。發起者是集結隊長、決定目標與出發時間，首版不額外複製其加成到所有人。
5. 出發後共用從發起城到目標的路徑，速度取成員最慢值；各玩家 march 記錄引用 rallyId，地圖只畫一支集結隊與人數徽記，避免重複五支同位置模型。
6. 抵達取得營地結算權、凍結種子與输入、跑一次戰鬥；若營地已被先打掉，所有人無戰損、無獎勵返程。不能只在發起時檢查營地。
7. 結算後存活部隊各自從目標回自己的主城，獎勵到家才入庫；傷兵按本人醫館規則處理、主將仍占用至返程完成。

- 集結準備期：成員可退出／召回；隊長取消則全隊折返，不能換人接任繼續使用舊倒數。遲到／失去盟籍的成員不參戰，依當前位置返程。
- 集結出發後：名單不可增減；隊長可整隊撤回，但須早於戰鬥凍結；一般成員不能單獨抽兵改變已出發隊伍。離盟者仍完成已出發遠征及收益／戰損，之後返家，不再享有新的盟員操作。
- 抵達並開始結算後，不接受取消／召回。勝負與戰損先持久化，再分別套用；斷線不取消、不改種子。
- 發起者離盟：準備中取消；已出發依凍結名單完成，既有隊長仍只能查看／發出整隊召回，不可替前聯盟建立新行動。
- 一名玩家可以不同主將參加不同集結，但沿用最多三支行軍限制，不能繞過單主將同時一行軍。
- 個人容量按自己的主堡計算，不借用發起者的高等級；發起者的主堡只控制全隊總容量。例如自己主堡 Lv.3，可派磐盾衛 100＋鳴弦手 120＋裂蹄騎 80，共 300；主堡 Lv.4 的個人上限建議提高到 400。主將統率不再額外壓低集結或援軍人數；普通行軍的既有統率規則不變。
- 集結與援軍模式須由伺服器用途判定，不能讓客戶端自行傳大容量或「忽略統率」旗標。調整出征驗證時須保留普通行軍限制，並測試不能偽造集結／援軍用途繞過統率。
- 戰鬥規格建議新增由伺服器選擇的集結模式：攻方最多十五小隊、守方目前營地仍最多五小隊；援軍城防模式則最多七個守方小隊。沒有援軍的 PvP／遠征／營地單打仍維持原五對五上限。保留原傷害公式與二十回合上限，擴充陣列／目標選擇／結果映射及戰報顯示，測試原有相同輸入／種子結果不變。
- 十五小隊會增加每回合行動數，不能只放寬驗證上限就視為完成；S6-5 必須量測五人混兵的戰力／戰損，與五人單兵種比較，確認分隊不意外複製主將加成。必要的平衡數值調整需另列提案核准。

### 獎勵與傷亡

- 勝利只生成一份原營地獎勵池，**不因五人參加乘五倍**。PvE BOSS 的特殊獎勵另案。
- 貢獻採本隊對敵人造成的實際有效傷害（不含溢出傷害）；全部為零則以參戰兵數作分配權重。離隊／未到齊者沒有貢獻。
- 每一種資源、每一種道具分開按權重比例分，先整數向下取整，再按小數餘額大者分剩餘單位；同餘額用穩定 participantId 排序。總量必須恰好等於獎勵池，不複製道具。
- 只有一件的道具可能只給一人；加入前和戰報明示此規則。輸／平沒有勝利獎勵；每位參戰主將沿用既有修練規則一次，不按人數加倍。
- 每個戰鬥小隊保存 ownerId／marchId／heroId 對應；傷亡依該隊結果回原玩家，不平均分攤。主將在戰鬥中的倒下不刪除角色。
- 回城入庫和戰損／修練各有獨立 receipt，重放戰報不重複加資源、道具、修練或部隊。

## 10. 資料、持久化與鎖

### 最小模組邊界

- `shared/.../Social/`：成員權限、幫助、領地、駐軍／集結的純整數規則與資料型別；不引用 Unity、HTTP、時間服務。
- `server/.../Social/AllianceService`：驗證身分、排程、協調與快照；呼叫既有玩家修改入口。
- `Persistence/IAllianceStore`：聯盟域儲存，提供 InMemory 和 Supabase 實作。需要原子性的聯盟域指令以 Supabase PostgreSQL transaction/RPC 執行；不引入另一個資料庫、訊息佇列或分散式服務。
- 客戶端負責展示預測時間／送意圖，伺服器重新算權限、費用、容量、路徑、結果。

### 權威資料

| 資料 | 權威來源與必要欄位 |
| --- | --- |
| alliances | id、version、名稱／簡稱唯一鍵、公告、加入模式、狀態；不在玩家存檔各放一份可修改盟籍 |
| alliance_members | playerId 唯一、allianceId、role、joinedAt、membershipEpoch；盟主轉讓／人數上限在同一聯盟域交易處理 |
| membership_cooldowns / applications | playerId 的再入盟時間、申請與到期時間；退出仍保留冷卻紀錄 |
| chat | allianceId、遞增 sequence、senderId、operationId、serverTime、text、moderation；限量查詢／清理 |
| flags | allianceId、slot、位置、完成時間、冷卻、version；覆蓋索引可重建，旗幟記錄是權威 |
| help_requests | queueId、ownerId、membershipEpoch、狀態；實際隊列結束時間與已幫助收據在受益者 CityState，清單僅索引 |
| military operations | rallyId／garrisonId、參與者、狀態、容量預留、時間、種子、凍結輸入與 outcome、每位玩家套用進度 |
| 玩家 CityState | 真正的兵營／傷兵、被占用主將與 march、queueId、持久化 operation receipts；聯盟標籤只作可刷新展示快照 |

一份部隊只能有一個可操作歸屬。出征後兵不在兵營；military operation 的人數是已扣出部隊的凍結快照，不能再被拿來另派一隊。SQL／CityState Schema 採新增欄位、旧 enum 不改名，舊玩家預設無聯盟。

### 鎖順序與多段處理

初版沿用**單一遊戲伺服器實例**。聯盟元資料用短時間 SocialGate 序列化；不要持有此鎖跑戰鬥或等待玩家存檔。之後若量測成瓶頸才拆每盟鎖，不能未具跨程序協調就開多實例。

**2026-10-12 實作補充**：`AllianceMetadataStore` 僅在一次目錄 Load／Save I/O 持有 metadata gate，玩家修改期間已釋放。多段寫入另經單伺服器 operation sequence 序列化，避免整份 JSON 舊快照覆蓋新資料；唯讀 Snapshot／同盟查詢不等待此長序列。禁止同時持有 metadata gate 與玩家 Gate、或兩位玩家 Gate。完成所有玩家 ACK 後清掉營地的大陣容／戰報 payload，保留 terminal 完成 ID、原擁有者結果與城市收據。背景每秒檢查變更／到期時間，空閒不重讀資料，錯誤按 1～30 秒退避；離線攻方的援軍城防也可復原。正式多實例與大規模效能仍須另行設計與驗證。

1. 取 SocialGate，驗證盟籍／權限／version，建立持久化 operationId 及必要席位／領地預留；持久化成功才釋放。
2. 釋放 SocialGate 後，透過 ModifyCityAsync 取得**一位**玩家 Gate，推進時間、查收據、套用一次效果並立即存檔。下一位玩家必須在前一位 Gate 釋放後處理。
3. 再取 SocialGate，按 operationId／version 更新進度，不能用舊快照覆蓋整份聯盟。全數持久化後才回完成與廣播。
4. HTTP／WebSocket 推播不在 Gate 裡等待。客戶端收到 pending／重連時按 operationId 查詢，不生成新請求重扣。

**禁止的鎖圖：SocialGate 與 PlayerSession.Gate 同時持有；兩位玩家 Gate 同時持有。** LoadLock 只經既有玩家入口，不在聯盟方法自行換序。

未完成預留不是無限期卡住：背景工作每秒檢查變更／到期行動，失敗採退避重試；開機先讀未完成操作再開放衝突功能。永久不合法者進可恢復取消／返還流程，不能只刪帳面紀錄。遇「不知道是否提交成功」必須查收據，不先退款。

### 典型跨資料操作與崩潰恢復

- **創盟／插旗付款**：先持久化名稱／旗位預留與支付操作；玩家扣款與 debitReceipt 同存；再提交聯盟／旗狀態。崩潰後讀 receipt 完成提交；確定不能完成才用唯一 refundId 退款一次。未完成時不顯示有效領地／可用聯盟。
- **加入兩盟競態**：資料庫 playerId 唯一約束＋聯盟域交易；同時申請可以，同時成為兩盟不行。更新 CityState 標籤失敗不影響盟籍權威。
- **援軍防守**：凍結駐軍記錄及其 version，收援城進 settlement 中；計算 outcome。城主自身戰損與包含援軍結果的 defender receipt 必須同存，之後才依 operationId 套用援軍擁有者、攻方。所有相依記錄確認保存前不釋放該城新戰鬥、不清收據；召回／離盟只排隊等待。開機依 defender receipt 與操作日誌接續，不重新算不同種子。
- **集結打營地**：以營地 ID＋本次重生 epoch 搶持久化 claim，普通單人打營地也走同一入口。先保存唯一種子／凍結輸入／結果，再逐玩家套用。勝利和重生時間保存於同一目標操作；失敗則釋放 claim 讓下一個攻擊者可打。不能沿用「重啟全清」的記憶體營地標記來保證一次性獎勵。
- **結算中途玩家上／下線**：由統一入口的 Gate／LoadLock 切換處理。保存失敗不回報成功，原操作繼續；處理中玩家不能花掉同一份預留部隊或資源。
- **收據清理**：只在操作有持久化 terminal tombstone、所有玩家結果均 ACK 後才可清理大 payload；保留小型完成 ID 防止舊請求重放。軍事與付款收據不能只用短 TTL 清掉；UI 聊天歷史七天不適用於經濟收據。

SQL 遷移另在實作批新增，RLS 禁止客戶端直改；service key 只由伺服器環境變數讀取。InMemory 必須支援相同原子語意與故障注入，不用「測試沒資料庫所以略過」代替驗證。

## 11. 協定與 UI 接入（命名草案）

請求都綁定已驗證 session；需要重試去重者帶 clientRequestId，伺服器派 operationId。回應包含 serverTimeMs、version／sequence；舊版本推播不得蓋掉新畫面。名稱在實作時一次同步 Messages.cs、WebSocketHandler.cs 和 README。

| 分組 | 請求／推播草案 |
| --- | --- |
| 聯盟 | alliance.list / get / create / join / apply / review / leave / kick / role / transfer / settings / dissolve；alliance.state / members |
| 聊天 | alliance.chat.send / history / report / moderate；alliance.chat.message |
| 幫助 | alliance.help.request / list / give / giveAll；alliance.help.changed |
| 援軍 | alliance.reinforce.send / recall / dismiss / settings；alliance.garrison.state |
| 旗幟 | alliance.flag.preview / build / cancel / remove；world.allianceTerritory |
| 集結 | alliance.rally.create / join / leave / cancel / list；alliance.rally.state / report |
| 恢復 | alliance.operation.get；pending / completed / rejected，錯誤碼可翻譯 |

- 聯盟頁籤：總覽／成員／聊天／互助／軍事／領地。無盟時顯示搜尋、推薦列表、建立，推薦只用可加入／人數等資料，不接 AI。
- 幫助頁顯示受益對象、隊列、剩餘可幫次數。軍事頁同時顯示「我派出的援軍」「城內援軍」「集結」，倒數與路程分開。援軍派遣提供三兵種數量控制，並列自己的派兵容量、目標城接收容量與所選總兵數；戰報可展開各兵種損失。
- 旗放置顯示覆蓋預覽、成本、付款人、施工時間與紅色無效原因；提交時伺服器再次判定，預覽不占位。
- 集結加入頁提供一位主將與三種兵各自的數量控制，清楚標示自己的主堡容量、已選總兵數、集結總容量／席位、抵達 ETA、出發後不能個別撤隊與獎勵分配。戰報以玩家分組展開各兵種戰損與個人收益。
- 補一組聯盟引導任務：加入 → 幫助一次 → 參與集結；首版不強迫新手建立聯盟或支付插旗費。
- GM 可唯讀查未完成 operation、盟籍與目標 claim；人工重試需要 Admin token 與稽核。第一版不提供「直接改聯盟 JSON」的公開管理入口。
